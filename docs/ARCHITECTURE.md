# Архитектура

Документ описывает, из чего состоит бот, как компоненты взаимодействуют и
почему приняты те или иные решения.

## Компоненты

| Модуль | Ответственность |
|---|---|
| `src/__main__.py` | Точка входа: `python -m src`. |
| `src/bot.py` | Подключение к ВКонтакте, Long Poll, сессии, команды, сборка запроса к модели, отправка ответа. |
| `src/gigachat_client.py` | OAuth, кэширование access token, повторы, вызов `chat/completions`, разбор ответа. |
| `data/knowledge_base.md` | Факты о курсах: программы, цены, сроки, форматы. |
| `prompts/alina_system_prompt.md` | Роль, стиль, границы темы, сценарии, запреты. |

Разделение намеренное: `gigachat_client.py` ничего не знает про ВКонтакте, а
`bot.py` — про формат OAuth-запроса. Клиент можно переиспользовать с любым
другим транспортом.

## Поток обработки сообщения

```
VkBotLongPoll.listen()
        │  VkBotEventType.MESSAGE_NEW
        ▼
VkBot.handle_message(event)
        │  отбрасываем исходящие (out) и некорректные from_id
        │  messages.setActivity(type="typing")
        ▼
VkBot._answer(user_id, text)
        │  normalize(text) → команда?
        ├── /start, «привет» → приветствие, история сбрасывается
        ├── /help            → справка
        ├── /reset           → история очищается
        ├── неизвестная /…   → справка
        └── обычный текст    → собираем messages
                                 [system prompt] + история + новое сообщение
                                        │
                                        ▼
                              GigaChatClient.chat()
                                        │
                                        ▼
                              VkBot._send(peer_id, reply, keyboard)
                                        │  split_message() ≤ 3500 символов
                                        ▼
                              VK messages.send
```

## Сборка системного промпта

Промпт собирается **один раз при старте** в `build_system_prompt()`:

1. Читается шаблон `prompts/alina_system_prompt.md`.
2. В него подставляются `{{KNOWLEDGE_BASE}}`, `{{SALES_FORM_URL}}`,
   `{{MANAGER_CONTACT}}`.
3. Если ссылка на форму не задана, в промпт добавляется отдельное указание не
   придумывать URL и давать контакт менеджера.

Готовая строка хранится в памяти и подставляется первым сообщением с ролью
`system` в каждый запрос. Это позволяет менять содержание без правки кода:
достаточно отредактировать markdown-файлы и перезапустить бота.

## Состояние диалога

История хранится в словаре `{user_id: {"history": [...], "last_seen": ts}}`:

- глубина ограничена `MAX_HISTORY_MESSAGES` (по умолчанию 12 сообщений);
- при превышении удаляются самые старые записи;
- раз в 100 обработанных событий вызывается `_cleanup_sessions()` и удаляются
  сессии, неактивные более 24 часов.

Хранение в памяти — осознанный компромисс: для одного сообщества это дешевле и
проще, чем база данных, а потеря контекста при перезапуске не критична.
Переход на Redis/SQLite локализован в двух методах: `_history()` и
`_trim()`.

## Клиент GigaChat

### Авторизация

1. `POST {GIGACHAT_OAUTH_URL}` с заголовком `Authorization: Basic <ключ>`,
   уникальным `RqUID` и телом `scope=...`.
2. Из ответа берётся `access_token` и `expires_at`.
3. Токен кэшируется; обновление происходит за 60 секунд до истечения.
4. На `401` токен инвалидируется и запрос повторяется один раз с новым.
5. Доступ к кэшу защищён `threading.Lock` — на случай, если бота запустят
   в несколько потоков.

`GET /models` используется как дешёвая проверка ключа при старте: список
моделей не расходует токены генерации.

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Сетевая ошибка | До 3 попыток, пауза 2 с, затем 4 с. |
| `401` | Одно обновление токена и повтор. |
| `429`, `5xx` | До 3 попыток, пауза из `Retry-After` (в пределах 1–30 с). |
| Прочие `4xx` | `GigaChatError` без повторов. |
| Пустой ответ | `GigaChatError`. |

На уровне бота `GigaChatError` превращается в вежливый fallback с контактом
менеджера, а неудачное сообщение удаляется из истории, чтобы не отравлять
следующий запрос.

## Слой ВКонтакте

- **Long Poll**, а не Callback API: не нужен публичный HTTPS-эндпоинт и
  домен — бота можно запустить на ноутбуке.
- **Разбиение ответа.** ВКонтакте ограничивает длину сообщения; `split_message()`
  сначала пробует абзацы, затем слова, и только потом режет по символам.
- **Клавиатура.** Кнопка «Оставить заявку» создаётся один раз при старте и
  прикрепляется к каждому ответу. Если ВК отклонит клавиатуру, сообщение
  отправляется повторно без неё — ответ важнее кнопки.
- **Переподключение.** `ReadTimeout` — штатное поведение Long Poll; прочие
  ошибки логируются, и цикл перезапускается через 5 секунд.

## Конфигурация и секреты

`python-dotenv` загружает `.env` из корня проекта. Все значения читаются через
хелперы `env`, `env_bool`, `env_int` — с дефолтами и мягкой валидацией.
Отсутствие обязательных переменных (`VK_TOKEN`, `VK_GROUP_ID`,
`GIGACHAT_AUTH_KEY`) останавливает запуск с понятным сообщением.

Логи пишутся в stdout и в `bot.log` (UTF-8). `urllib3`, `requests`, `vk_api`
принудительно переведены на уровень `WARNING`: даже при `LOG_LEVEL=DEBUG`
заголовки `Authorization` не попадают в вывод.

## Точки расширения

- **Другой мессенджер** — реализовать транспорт с тем же интерфейсом
  `handle_message` / `_send`, логика диалога останется общей.
- **Вебхуки ВК** — заменить `VkBotLongPoll` на HTTP-обработчик.
- **Персистентность** — вынести `_history`/`_trim` в хранилище.
- **Метрики** — обернуть `_answer` счётчиками диалогов и тем обращений.
- **Стриминг** — `GigaChatClient.chat(stream=True)` и отправка по мере
  поступления токенов (потребует правок транспорта).
