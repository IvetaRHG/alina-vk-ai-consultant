# Алина — AI-консультант для сообщества ВКонтакте

Чат-бот, который отвечает на вопросы клиентов онлайн-университета **Zerocoder**
прямо в сообществе ВКонтакте: подбирает программу обучения, объясняет форматы
и сроки, а в подходящий момент предлагает оставить заявку.

Работает на **GigaChat API** (Сбер) — российская LLM, без VPN и зарубежных
провайдеров. Реализован на Python, без фреймворков: только `vk_api`,
`requests` и собственная логика диалога.

## Задача

Сообщество ВКонтакте получает десятки однотипных вопросов: «сколько стоит»,
«есть ли рассрочка», «подойдёт ли мне курс, если я не айтишник». Менеджер
отвечает на них вручную и теряет время на тех, кто ещё не готов покупать.

**Решение:** бот-консультант, который знает каталог курсов и отвечает в стиле
живого консультанта — но строго по базе знаний, без выдуманных цен и обещаний.
Заявку он не оформляет, а передаёт в отдел продаж по ссылке на форму.

Основная сложность была не в API, а в поведении: LLM охотно фантазирует про
цены и гарантии трудоустройства. Поэтому роль, границы темы и запреты описаны
в отдельном системном промпте, а факты вынесены в редактируемую базу знаний.

## Возможности

- **Диалог с контекстом** — помнит последние 12 сообщений (настраивается),
  поэтому понимает уточнения вида «а если в рассрочку?».
- **Ответы строго по базе знаний** — промпт запрещает придумывать факты;
  если данных нет, бот честно говорит об этом и даёт контакт менеджера.
- **Команды**: `/start` — приветствие, `/help` — что умеет, `/reset` — сброс диалога.
- **Кнопка «Оставить заявку»** — ссылка на форму (Яндекс Формы, Tilda, CRM)
  приходит вместе с ответом, когда пользователь готов к следующему шагу.
- **Устойчивость к сбоям** — переподключение к Long Poll, повторные запросы к
  LLM при `429`/`5xx`, автоматическое обновление access token.
- **Длинные ответы не теряются** — текст делится на части по абзацам и словам
  в пределах лимита ВКонтакте.
- **Секреты вне кода** — всё в `.env`, файл в `.gitignore`, токены не попадают
  в логи даже на уровне `DEBUG`.

## Как это работает

```
ВКонтакте
   │  сообщение пользователя
   ▼
VK Long Poll API  ──►  bot.py
                        │  1. команды и служебные ответы
                        │  2. история диалога пользователя (in-memory)
                        ▼
                  GigaChatClient
                        │  OAuth: ключ авторизации → access token (кэш ~30 мин)
                        ▼
                  GigaChat API
                        │  system prompt + база знаний + история
                        ▼
                  ответ модели
                        │  разбивка на части ≤ 3500 символов
                        ▼
                 messages.send  ──►  пользователь
```

Системный промпт собирается один раз при старте: в шаблон
`prompts/alina_system_prompt.md` подставляются база знаний, ссылка на форму и
контакт менеджера. Дальше на каждый запрос уходит только история диалога.

Подробнее о компонентах и принятых решениях — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

| LLM | GigaChat API (`GigaChat-2`, опционально `Pro` / `Max`) |

## Быстрый старт

```bash
git clone https://github.com/IvetaRHG/alina-vk-ai-consultant.git
cd alina-vk-ai-consultant
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env             # Windows: Copy-Item .env.example .env
```

Заполните `.env`: ключ сообщества ВКонтакте, ID сообщества и ключ GigaChat API.
Затем из корня проекта:

```bash
python -m src
```

Полная инструкция — получение ключей, права токена ВК, сертификаты Минцифры,
типовые ошибки — в [docs/SETUP.md](docs/SETUP.md).

## Настройка поведения

Бот не требует правок кода, чтобы менять содержание:

- **Факты** — `data/knowledge_base.md`: программы, цены, сроки, форматы.
  Обновили файл → перезапустили бота.
- **Характер и правила** — `prompts/alina_system_prompt.md`: роль, тон,
  сценарии диалога, запрет на выдуманные факты и гарантии.
- **Модель и лимиты** — переменные `GIGACHAT_MODEL`, `MAX_HISTORY_MESSAGES`,
  `LOG_LEVEL` в `.env`.

## Инженерные решения

- **Кэш access token.** GigaChat выдаёт токен на ~30 минут; клиент хранит его
  и обновляет за минуту до истечения, а на `401` принудительно перевыпускает.
  Потокобезопасно через `threading.Lock`.
- **Повторные запросы.** `429` и `5xx` повторяются до трёх раз с учётом
  заголовка `Retry-After`; сетевые ошибки — с нарастающей паузой.
- **Проверка ключа без расхода токенов.** При старте вызывается `GET /models`,
  а не генерация — дешёвая диагностика конфигурации.
- **Защита логов.** HTTP-логгеры (`urllib3`, `requests`, `vk_api`) принудительно
  переведены на `WARNING`, чтобы заголовки `Authorization` не попадали в вывод.
- **Разбиение сообщений.** Алгоритм режет ответ по абзацам, затем по словам,
  и только в крайнем случае — по символам, не разрывая смысл.
- **Сессии с TTL.** История хранится в памяти и чистится через 24 часа
  бездействия, чтобы бот не рос в памяти на долгой дистанции.

## Безопасность

- Секреты только в `.env`, который исключён из Git; в репозитории есть лишь
  `.env.example` с пустыми значениями.
- Сертификаты (`*.pem`, `*.crt`) и логи (`*.log`) также не публикуются.
- Проверка SSL включена по умолчанию; `GIGACHAT_VERIFY_SSL=false` — только для
  локальной отладки.
- Бот не собирает персональные данные: заявка уходит во внешнюю форму.

## Ограничения

- Бот консультирует, но не заменяет менеджера: цены, скидки, рассрочка и даты
  старта подтверждаются человеком.
- История диалога хранится в памяти процесса — при перезапуске сбрасывается.
- Один экземпляр обслуживает одно сообщество; горизонтального масштабирования
  нет (для одного сообщества это не требуется).
- LLM может ошибаться: перед публикацией ответы стоит проверить на типовых
  вопросах и обновить базу знаний.

## Что можно добавить

- Хранение истории в Redis или SQLite, чтобы диалог переживал перезапуск.
- Метрики: количество диалогов, конверсия в заявку, темы обращений.
- Вебхуки ВКонтакте вместо Long Poll для меньшей задержки.
- Тесты на сборку промпта, разбиение сообщений и обработку ошибок API.
